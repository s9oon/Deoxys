# Desktop app

A Tauri 2 app in `desktop/`: a SolidJS frontend in `desktop/src`, plus a Rust
side in `desktop/src-tauri`. It's a separate Cargo project, not part of the
root workspace (see [shared-types.md](shared-types.md#the-cargo-workspace)).

## Running in dev

Start the backend first, then the app:

```sh
cargo run -p backend          # from the repo root
cd desktop && npm run tauri dev
```

The window shows the message returned by the backend. If the backend isn't
running, it shows `error: ...` instead.

## Frontend ↔ Rust (IPC)

The frontend calls Rust functions by name. There's no HTTP between them.

```rust
// desktop/src-tauri/src/lib.rs
#[tauri::command]
async fn get_hello() -> Result<Hello, String> { ... }

// registered in run():
.invoke_handler(tauri::generate_handler![greet, get_hello])
```

```ts
// desktop/src/App.tsx
import type { Hello } from "./ipc/Hello";   // generated by ts-rs
invoke<Hello>("get_hello")
```

- **Arguments and return values travel as JSON**, so they need `Serialize`/`Deserialize`.
- **Errors come back as a rejected promise.** `Result<_, String>` is the simplest error type that serializes.
- **The command name is a plain string in TypeScript.** Nothing checks it. `tauri-specta` can generate typed wrappers if that becomes a problem.

## Talking to the backend

Only the Rust side calls the backend, using `reqwest`. The response is
parsed straight into `shared::Hello`.

`BACKEND_URL` is read at **compile time**:

```rust
const BACKEND_URL: &str = match option_env!("BACKEND_URL") {
    Some(url) => url,
    None => "http://localhost:3000",
};
```

It's compile time because the app runs on users' machines, and they won't
set env vars. The value is baked into the binary when it's built.

- **In dev:** unset, so `http://localhost:3000` is used.
- **For a release:** set it when building (see below).
- **Never put secrets in it.** Anything baked into a desktop binary can be extracted.

## Building installers

```sh
cd desktop
$env:BACKEND_URL = "https://your-backend"   # PowerShell
npm run tauri build
```

Output goes to `desktop/src-tauri/target/release/bundle/`:

| File | Tool | Good for |
|---|---|---|
| `msi/*.msi` | WiX | IT and Group Policy deployment; Windows Installer runs it |
| `nsis/*-setup.exe` | NSIS | handing to people; per-user installs without admin rights |

`"targets": "all"` in `tauri.conf.json` builds both. Set it to `["nsis"]` or
`["msi"]` to build only one.

Notes:

- **The first build is slow.** Tauri downloads WiX/NSIS, and the release profile (LTO, `codegen-units = 1`) compiles slowly.
- **The installers aren't signed**, so Windows SmartScreen warns. Click More info → Run anyway. Removing the warning needs a code-signing certificate.
- **`productName` is still `"desktop"`** and `identifier` is `com.harry.desktop`. Rename both before shipping.
